# DECISIONS

Short entries: chose X over Y because Z. Newest last. Superseded entries are struck through and point to their replacement.

1. **n8n 2.49.6, pinned** (`n8nio/n8n:2.49.6`) over a floating `latest` tag, because the same repo must behave the same everywhere; upgrades follow the runbook in the README.
2. ~~**Postgres 16.6-alpine**~~ → superseded by 13.
3. **Owner account from environment variables** (`N8N_INSTANCE_OWNER_MANAGED_BY_ENV` + bcrypt hash generated by `make setup`) over clicking through the setup screen, so a fresh clone and CI boot to a usable instance with no manual step.
4. **Workflows and credentials go in through the n8n CLI** (`import:workflow`, `import:credentials`) inside the running container, rather than creating them through the public REST API. The CLI keeps fixed credential and workflow IDs, so cross-workflow references and credential links survive a fresh import. Plaintext credential JSON is piped over stdin into a `umask 077` temp file and deleted right after. The spec allows "REST API or documented steps"; this is the scripted equivalent. Activation: see 15.
5. **Fixed workflow IDs** (`lpMainIntake0001` …) so `Execute Workflow` nodes reference sub-workflows stably across instances.
6. ~~**Task runners in internal mode**~~ → superseded by 14.
7. **`$env` access enabled in workflows** for non-secret settings (base URLs, model name, thresholds, flags) over hardcoding them, because tests must repoint base URLs at the mock server. API keys stay in n8n credentials, never in `$env` expressions. Exception: `WEBHOOK_HMAC_SECRET` is read with `$env` in the signature Code node, because n8n credentials can't be read from a Code node; it never appears in exported JSON.
8. **Test overlay file** (`docker-compose.test.yml` + `test` profile) over editing `.env` for tests, because Compose `environment:` overrides `env_file`, so the same `.env` serves both dev and e2e runs.
9. **Small `.env` reader** (`scripts/envfile.py`, ~40 lines) over adding `python-dotenv` (CONVENTIONS §1: plain code under 50 lines).
10. **Harness dependencies:** FastAPI + uvicorn (mock server, per spec), httpx (HTTP client for tests and admin scripts), bcrypt (owner password hash for the env-managed owner).
11. **Showcase frames rendered from Stitch's exported HTML** with Playwright (official Docker image, nothing installed locally) instead of using Stitch's PNGs directly, because the spec asks for 1920×1080 frames while Stitch exports full pages 1600 px wide, and because the HTML had to be corrected (an invented "40 %" claim, real-looking `.com`/`.io` domains, LinkedIn sources) before the images could be used.
12. **Two intake workflows + a shared `sub-validate`** over one `main-lead-intake` with both triggers, because n8n refuses to start a workflow that has a Form Trigger and a "Respond to Webhook" node, and the webhook needs Respond nodes for 401/422/202. Validation lives once in `sub-validate`; `main-lead-intake` keeps its spec name and becomes the pipeline, started with "wait for completion" off so the webhook answers within a second.
13. **Postgres 17.6-alpine** over 16, because n8n 2.49 logs that Postgres 16 "is outside the supported range and receives compatibility support only". The leads database lives on the same server.
14. **External task runners** (`n8nio/runners:2.49.6` container, `N8N_RUNNERS_MODE=external`) over internal mode, because n8n 2.x marks internal mode deprecated and slated for removal. `node:crypto` is allowed in the runner only; nothing else.
15. **Activation through the public API after import** over `import:workflow --activeState=fromJson`, because n8n only supports that flag in queue/multi-main mode. `make import` imports, restarts n8n, then activates in dependency order worked out from the Execute Workflow references and `errorWorkflow` settings (`activation_order`, unit-tested), because n8n won't publish a workflow whose sub-workflows aren't published. A naming-based order broke on the first fresh rebuild in M2. The API key is created from the owner login when `.env` has none or a stale one.
16. **A Postgres `leads` table** (separate `leadpilot` database, plain SQL migrations in `db/migrations/` applied by `make migrate`) over n8n Data Tables, because Data Table IDs are random per instance and would break a fresh import, and SQL gives an atomic "insert unless seen in 24 h" for idempotency plus a one-line retention purge. Not Alembic: there's no Python app; the CONVENTIONS exception for n8n-managed schema applies to n8n's own tables only, and these few SQL files are versioned and applied in order.
17. **HMAC over the raw request body** (`X-Signature-256: sha256=<hex>`, GitHub-style, compared with `timingSafeEqual`) over signing the parsed JSON, because senders sign bytes and re-serialised JSON can differ. Replays inside 24 h are absorbed by the idempotency check.
18. **`N8N_WEBHOOK_URL`** instead of the spec's `WEBHOOK_URL`, because n8n 2.x deprecated the old name.
19. **Spam is stored without personal data** (id, hash, source, reasons) so spam rates are measurable without keeping spammers' details; the response is a neutral 200 so spammers learn nothing about the rules.
20. **Enrichment degrades instead of failing**: Tavily and Gemini nodes retry 3 times, 3 s apart, then continue on their error output (`onError: continueRegularOutput`), and the lead goes on as `partial` or `enrichment_failed` (scored on form data only). This matches the spec's recoverable "enrichment failed" state. The error workflow is kept for failures that stop a lead outright (M6).
21. **A code-level grounding guard after the model** over trusting the prompt alone: any profile value or fact whose source URLs were not among the pages actually read is dropped and counted. It is deterministic and testable, and it backs the "every claim traceable to a source" promise.
22. **Gemini via HTTP Request with `responseSchema` and `thinkingConfig.thinkingBudget: 0`**: structured output without a parsing layer, and no thinking tokens for a summarising task (cheaper and faster on 2.5 Flash). The model name stays in `LLM_MODEL`.
23. **The mock picks its Gemini answer by the request's response schema** (e.g. a `what_they_do` property means a profile request) rather than a marker in the prompt, so production prompts carry no test-only text.
24. **Score maths in one pure function inside the "Compute score" Code node**, unit-tested by running the exported node code under Node.js against a Python reference (300 seeded random rating sets plus edge cases), over re-implementing the formula in Python and testing that. The test exercises exactly what n8n runs, so "the score always equals the weighted ratings" is proven on the real artefact.
25. **Invalid or missing ratings count as 0 and are listed in `issues`** rather than failing the lead or clamping (a `4` is not silently a `3`). A wrong model answer can only lower a score, never inflate it; reviewers see the issue in Slack (M4).
26. **No contact name or email in model prompts.** Scoring and enrichment send business data only (role, company, email domain, budget, message, research). The free Gemini tier may use inputs, and the model doesn't need to know who the person is.
27. **The workflow linter compiles every Code node** (Node.js `vm.Script`) after a builder bug produced a syntax error only n8n caught at run time. CI and `make lint` now fail on it.
28. **Approval = Slack message (HTTP `chat.postMessage`) + an n8n Wait-node form**, instead of the Slack node's "Send and Wait for Response". The reviewer experience is the same (a button in Slack opens an n8n form: approve / approve with edits / reject, with the draft pre-filled), and that's what Send-and-Wait does internally. Doing it explicitly keeps the message `ts`, so the outcome can update the same message (`chat.update`) and reminders can be threaded under it. It also runs against a mock in CI, and the Slack app needs only `chat:write`: no interactivity URL or signing secret. A public `N8N_WEBHOOK_URL` (the tunnel) is still needed so the form link opens for reviewers.
29. **Reminders from a scheduled workflow** (`approval-reminders`, every 15 minutes, also runnable via the ops webhook), because a waiting execution is paused and can't post anything itself. Each lead is reminded once (`reminder_sent_at`).
30. **The reviewer's name is a required form field**, because a link-opened form doesn't know the Slack user. It is stored with the decision.
31. **Any change to the pre-filled subject or body counts as "approve with edits"**, even if "Approve" was chosen, so what is sent is always what the reviewer last saw.
32. **Eval auto-approve applies only to leads posted with `"_eval": true`**, and only when `DEMO_MODE=true` and `EVAL_AUTO_APPROVE=true`. Normal leads on the same instance still wait for a person.
33. **Draft checks in code** (`sub-draft` › "Check draft"): forbidden phrases quoted in `reply_style.md`, figures that aren't in the message, research or style guide, citations of unread pages, missing booking link, length. They are shown to the reviewer as warnings; only the booking link is fixed automatically. The model's judgement is not trusted for these.
34. **The test stack fakes every external service** (Tavily, Gemini, Slack and HubSpot via `*_BASE_URL`, SMTP via mailpit), so the full write path runs in CI. A separate dry-run pass (`make test-e2e-dryrun`, `DRY_RUN=true`) checks that nothing is written at all.
35. **An ops webhook** (`POST /webhook/ops`, header `X-LeadPilot-Ops-Token`) runs reminders, the digest and lead replays on demand, so operators and tests don't need n8n's UI.
