# DECISIONS

Short entries: chose X over Y because Z. Newest last. Superseded entries are struck through and point to their replacement.

1. **n8n 2.49.6, pinned** (`n8nio/n8n:2.49.6`) over a floating `latest` tag, because the same repo must behave the same everywhere; upgrades follow the runbook in the README.
2. ~~**Postgres 16.6-alpine**~~ → superseded by 13.
3. **Owner account from environment variables** (`N8N_INSTANCE_OWNER_MANAGED_BY_ENV` + bcrypt hash generated by `make setup`) over clicking through the setup screen, so a fresh clone and CI boot to a usable instance with no manual step.
4. **Workflows and credentials go in through the n8n CLI** (`import:workflow`, `import:credentials`) inside the running container, rather than creating them through the public REST API. The CLI keeps fixed credential and workflow IDs, so cross-workflow references and credential links survive a fresh import. Plaintext credential JSON is piped over stdin into a `umask 077` temp file and deleted right after. The spec allows "REST API or documented steps"; this is the scripted equivalent. Activation: see 15.
5. **Fixed workflow IDs** (`lpMainIntake0001` …) so `Execute Workflow` nodes reference sub-workflows stably across instances.
6. ~~**Task runners in internal mode**~~ → superseded by 14.
7. **`$env` access enabled in workflows** for non-secret settings (base URLs, model name, thresholds, flags) over hardcoding them, because tests must repoint base URLs at the mock server. API keys stay in n8n credentials, never in `$env` expressions. Exception: `WEBHOOK_HMAC_SECRET` is read with `$env` in the signature Code node, because n8n credentials can't be read from a Code node; it never appears in exported JSON.
8. **Test overlay file** (`docker-compose.test.yml` + `test` profile) over editing `.env` for tests, because Compose `environment:` overrides `env_file`, so the same `.env` serves both dev and e2e runs.
9. **Small `.env` reader** (`scripts/envfile.py`, ~40 lines) over adding `python-dotenv` (CONVENTIONS §1: plain code under 50 lines).
10. **Harness dependencies:** FastAPI + uvicorn (mock server, per spec), httpx (HTTP client for tests and admin scripts), bcrypt (owner password hash for the env-managed owner).
11. **Showcase frames rendered from Stitch's exported HTML** with Playwright (official Docker image, nothing installed locally) instead of using Stitch's PNGs directly, because the spec asks for 1920×1080 frames while Stitch exports full pages 1600 px wide, and because the HTML had to be corrected (an invented "40 %" claim, real-looking `.com`/`.io` domains, LinkedIn sources) before the images could be used.
12. **Two intake workflows + a shared `sub-validate`** over one `main-lead-intake` with both triggers, because n8n refuses to start a workflow that has a Form Trigger and a "Respond to Webhook" node, and the webhook needs Respond nodes for 401/422/202. Validation lives once in `sub-validate`; `main-lead-intake` keeps its spec name and becomes the pipeline, started with "wait for completion" off so the webhook answers within a second.
13. **Postgres 17.6-alpine** over 16, because n8n 2.49 logs that Postgres 16 "is outside the supported range and receives compatibility support only". The leads database lives on the same server.
14. **External task runners** (`n8nio/runners:2.49.6` container, `N8N_RUNNERS_MODE=external`) over internal mode, because n8n 2.x marks internal mode deprecated and slated for removal. `node:crypto` is allowed in the runner only; nothing else.
15. **Activation through the public API after import** over `import:workflow --activeState=fromJson`, because n8n only supports that flag in queue/multi-main mode. `make import` imports, restarts n8n, then activates the error handler and sub-workflows before the trigger workflows (n8n won't publish a workflow whose sub-workflows aren't published). The API key is created from the owner login when `.env` has none or a stale one.
16. **A Postgres `leads` table** (separate `leadpilot` database, plain SQL migrations in `db/migrations/` applied by `make migrate`) over n8n Data Tables, because Data Table IDs are random per instance and would break a fresh import, and SQL gives an atomic "insert unless seen in 24 h" for idempotency plus a one-line retention purge. Not Alembic: there's no Python app; the CONVENTIONS exception for n8n-managed schema applies to n8n's own tables only, and these few SQL files are versioned and applied in order.
17. **HMAC over the raw request body** (`X-Signature-256: sha256=<hex>`, GitHub-style, compared with `timingSafeEqual`) over signing the parsed JSON, because senders sign bytes and re-serialised JSON can differ. Replays inside 24 h are absorbed by the idempotency check.
18. **`N8N_WEBHOOK_URL`** instead of the spec's `WEBHOOK_URL`, because n8n 2.x deprecated the old name.
19. **Spam is stored without personal data** (id, hash, source, reasons) so spam rates are measurable without keeping spammers' details; the response is a neutral 200 so spammers learn nothing about the rules.
